1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) defines the complete functional, non-functional, and technical requirements for the AI-Powered Emergency Green Corridor System developed by Team OrionCoders for HackOverflow 4.0. This document serves as the foundational blueprint for design, development, testing, and demonstration of the system within the hackathon timeline.
1.2 Scope
The system, titled "AI Green Corridor", is an intelligent emergency traffic management platform that:
Detects ambulances in real-time using AI computer vision on CCTV/camera feeds.
Automatically switches traffic signals to green on the ambulance's route.
Pushes geofenced alerts to nearby drivers via a Progressive Web App (PWA) installable on any modern smartphone browser.
Provides city-level oversight through a real-time web dashboard.
Predicts and pre-clears intersections ahead of the ambulance using route-planning algorithms.
The system operates without expensive hardware upgrades, leveraging existing smartphones and CCTV infrastructure.

2. Overall System Description
2.1 Product Perspective
The AI Green Corridor is a standalone smart city subsystem designed to integrate with existing urban traffic infrastructure. It interfaces with CCTV cameras, traffic signal controllers, and driver smartphones via a Progressive Web App. The system is hardware-light by design — it does not require specialized ambulance hardware, dedicated roadside units, or native app installations. It operates entirely through software running on commodity servers and any modern web browser.

No New Hardware: System must operate on existing smartphones and CCTV infrastructure.
No Backend Cloud Costs: Demo must run locally or on a free-tier cloud instance.
Max 8 Presentation Slides: As mandated by HackOverflow 4.0 rules.
Real-Time Constraint: Signal switching must occur within 3 seconds of detection.

4.2 Reliability & Availability
The backend must implement automatic reconnection for Socket.io clients (PWA, dashboard) with exponential backoff.
Redis must have a fallback: if Redis is unavailable, the system must degrade gracefully to direct in-memory event processing.
Camera feed watchdog: if no detection events received for 10+ seconds, auto-switch to GPS beacon mode and send status alert.
All critical services (backend, AI engine) must restart automatically via Docker restart: always policy.
System uptime target for demo: 99.9% over 36-hour hackathon period.
4.3 Security Requirements
All API endpoints must validate input against a defined JSON schema; reject malformed payloads with HTTP 400.
WebSocket connections must include an API key header for authentication (simple shared secret for hackathon).
Web Push payloads must not include personally identifiable information about ambulance patients or exact patient locations.
CORS must be configured to allow only trusted origins (dashboard domain + PWA domain).
VAPID private key must be stored as an environment variable; never committed to source control.
4.4 Scalability
Backend must support at least 500 concurrent WebSocket connections (Socket.io + Redis adapter).
AI detection engine must support parallel processing of 4 camera feeds simultaneously via Python multiprocessing.
MongoDB indexes on timestamp and zone fields for fast incident log queries.
Stateless backend design — horizontal scaling via Docker Swarm or Kubernetes (future).
4.5 Usability
PWA onboarding: new users must be able to select their mode (Driver/Ambulance), grant location permission, and enable push notifications within 30 seconds of first visit.
Dashboard must be readable in daylight conditions (no low-contrast elements); use minimum 4.5:1 WCAG AA contrast ratio.
All alert notifications must be actionable within 1 tap; no multi-step acknowledgement flows.
TTS alerts must play even when phone is in silent mode (emergency override).

5.2 Data Flow Description
Camera feed (RTSP or MP4 file) is ingested by the AI Detection Engine (detect.py).
YOLOv8 detects ambulance; ByteTrack assigns track ID and computes direction vector.
Detection event JSON is posted to POST /api/detection on the Node.js backend.
Backend publishes event to Redis Pub/Sub channel "detections".
Redis subscriber triggers A* pathfinding to compute route to hospital.
IntersectionManager schedules signal switches along route with ETA-based timing.
Signal state changes are emitted via Socket.io to all connected dashboard and app clients.
Web Push notification sent to subscribed PWA service workers of all drivers within 500m geofence via VAPID web-push library.
PWA displays alert overlay, plays TTS via Web Speech API, triggers vibration pattern, and updates live map.
React dashboard updates signal colors, ambulance marker position, and incident log in real time.
After ambulance passes, cooldown timer triggers signal revert and "Safe to merge" Web Push to drivers.
Full incident is persisted to MongoDB with all metrics for analytics.
